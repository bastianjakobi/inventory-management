Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

System architecture

Three tiers, two processes, one HTTP boundary.

Data flow

How a filter change becomes a re-rendered chart.

Request lifecycle

  1. Filter change. The user changes a dropdown in FilterBar.vue. State lives in module-level refs in useFilters.js, so every view shares one singleton.
  2. Fetch. A view watches the filters, calls getCurrentFilters(), and passes the result to a method in api.js. Values equal to all are omitted from the query string.
  3. Route. FastAPI matches the /api/* route and receives the query params.
  4. Filter. The handler runs apply_filters() (warehouse, category, status) and filter_by_month() over the in-memory lists from mock_data.py.
  5. Validate. Where a response_model is set, Pydantic validates and serializes the result.
  6. Render. The view stores raw data in refs (allOrders, inventoryItems) and derives totals, chart series and tables with computed properties.

Things worth knowing

Findings from reading the code, not from running it.

Client calls routes the server does not have gap

api.js defines getTasks, createTask, toggleTask, deleteTask, createPurchaseOrder and getPurchaseOrderByBacklogItem. main.py has no /api/tasks or /api/purchase-orders handlers, only a CreatePurchaseOrderRequest model. App.vue calls getTasks() on mount; that request would 404, but the error is caught and logged, so the UI still renders.

State is process-local by design

Data is read from JSON once when mock_data.py is imported. Nothing is written back, so restarting the server resets everything. This also means the app is single-process only.

Hard-coded URLs and open CORS demo only

The API base URL is fixed to http://localhost:8001/api in api.js, and the server allows all origins with credentials. Both are fine for a local demo and would need configuration for any real deployment.

Dead view minor

views/Backlog.vue is neither routed nor imported anywhere. Backlog data reaches the UI through the Dashboard and BacklogDetailModal.vue.
